☑️ 1. 왜 만들려고 하는가?

✅ 1.1 문제 제기

• 부정확하거나 질 낮은 정보가 담긴 블로그가 양산되면서, 사용자는 원하는 정보를 얻기 위해 더 많은 시간을 탐색에 쏟아야 하는 비효율이 발생하고 있다. 수많은 정보를 접하며 유용하다고 판단한 페이지를 북마크에 저장하지만, 결국 북마크가 너무 많아져 폴더로 정리해도 정작 필요할 때 찾지 못하는 문제가 발생한다.

• 또한, 나중에 다시 봐야지라고 생각했지만 북마크하지 않고 지나친 페이지가 뒤늦게 중요하다고 판단될 때, 제목이 비슷하고 양이 방대한 검색 기록 속에서 해당 페이지를 다시 찾는 것은 거의 불가능에 가깝다.

✅ 1.2 문제 구체화 : 문제의 원인과 영향을 파악(Why → How)

• 왜 이런 문제가 발생했는가?

• 사용자(혹은 시장)는 이 문제 때문에 어떤 불편을 겪는가?

• 이 문제는 얼마나 자주/광범위하게 발생하는가?

✅ 1.3 기존의 대안 조사

• 브라우저 북마크 : 가장 기본적인 방법이지만, 수동 폴더 지정의 번거로움, ‘임시/영구’ 저장의 모호함, 제목 기반 검색의 한계가 명확하다.

• 메모 앱/서비스 (Notion) : 체계적인 관리는 가능하나, 모든 링크와 내용을 수동으로 ‘복사-붙여넣기’ 해야 하므로 정보 수집 과정의 흐름을 끊고 매우 비효율적이다.

• 탭 관리 도구 (Toby): 특정 ‘작업 단위’로 탭 그룹을 저장하는 데 유용하지만, 과거의 모든 웹 방문 기록을 자동으로 아카이빙하고 검색하는 목적과는 거리가 있다.

☑️ 2. 프로젝트의 목적 (Project Purpose)

흩어진 웹 서핑 기록을 '자동으로' 맥락에 맞게 아카이빙하여, 사용자가 필요할 때 원하는 정보를 '쉽고 빠르게' 재발견하고 활용할 수 있도록 돕는 지능형 웹 탐색 비서

• 자동 아카이빙 (Automatic Archiving): 브라우저 확장 프로그램을 통해 사용자가 방문하는 모든 페이지의 URL, 제목, 본문 텍스트 등 주요 정보를 로컬 또는 클라우드에 자동으로 저장한다.

• AI 기반 자동 분류 및 요약 (AI-Powered Tagging & Summary): 저장된 페이지의 콘텐츠를 AI가 분석하여 핵심 키워드를 자동으로 추출해 태그를 생성하고, 긴 글의 경우 핵심 내용을 요약하여 제공한다.

• 강력한 통합 검색 (Unified Powerful Search): 저장된 모든 아카이브를 대상으로 단순 키워드 검색을 넘어, 본문 전체 내용 검색(Full-Text Search), 태그, 도메인, 방문 시점 등 다양한 필터를 조합한 상세 검색 기능을 제공한다.

• 중요도 및 맥락 시각화 (Context & Priority Visualization): 페이지 체류 시간, 재방문 빈도 등 사용자의 행동 패턴을 기반으로 정보의 중요도를 시각적으로 표현하고, 어떤 검색을 통해 해당 페이지에 도달했는지 등 관련 맥락 정보를 함께 제공한다.
